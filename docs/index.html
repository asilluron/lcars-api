LCARS

Home control for a wall screen

An open-source home assistant styled after Star Trek’s LCARS. The panel runs on a Raspberry Pi; the API runs on your LAN and feeds it calendars, reminders, cameras, locks, and weather.

Panel · lcars-iot API · lcars-api How to run

Two pieces, one house

The wall screen and the server are separate open-source projects. They talk over your home network with NATS and protobuf—no cloud account required for the core path.

  • lcars-iot Native Rust panel (Slint). Renders on a Pi 5 with LinuxKMS, or on a laptop for development. This is the UI on the wall.
  • lcars-api Go server on a Mac mini, NAS, or Pi. Reads local calendar files, embeds NATS, proxies cameras and locks, and hosts the admin page.

What the panel can show

Each capability turns on when you point the API at a local source. Leave a setting unset and that endpoint stays off.

Calendar
Serves a directory of .ics exports, expands recurrence, and pushes lcars.calendar.updated when files change.
Reminders
A short to-do list in local Supabase. Admins add items; the panel marks them done.
Cameras
Catalog, snapshots, and live Annex-B streams via an optional Eufy proxy on the same machine.
Locks
List, lock, and unlock through Seam. The API key stays on the server; devices only talk to lcars-api.
Weather
Current conditions for a configured lat/long via Open-Meteo. No API key required.
Device tokens
Optional auth with Supabase. Issue and revoke tokens on the embedded admin page at /admin/.

How to run it

Keep everything on a trusted LAN. Without Supabase, the API is open to the network; with it, devices need tokens, but traffic is still for the home—not the public internet.

  1. 1 · Start the API

    On the machine that holds your calendars (Go 1.27+): 

    git clone https://github.com/asilluron/lcars-api.git
cd lcars-api
cp lcars.example.toml lcars.toml   # set calendar.dir, timezone, …
make run                           # NATS :4222, HTTP :8080
curl localhost:8080/healthz

  2. 2 · Point the panel at it

    On a laptop for a windowed preview, or on the Pi image via Balena device variables: 

    # from https://github.com/asilluron/lcars-iot
export NATS_URL=nats://192.0.2.10:4222
export LCARS_HTTP_URL=http://192.0.2.10:8080
cargo run -p lcars-app

    With device auth on, also set LCARS_DEVICE_USER and LCARS_DEVICE_SECRET. For tls:// NATS, set NATS_CA_B64 or NATS_CA_FILE.

  3. 3 · Optional: tokens, cameras, locks

    Run local Supabase for the admin page and reminders (supabase start), set eufy.url for cameras, and seam.api_key for locks. Full tables live in the lcars-api README.

Built for the LAN

NATS is the primary API; HTTP covers health, JSON mirrors, OpenAPI docs, and admin. Generated Rust types ship in lcars-api for microcontroller-friendly clients.
